# 最小可用骨架：带状态机的对话流

从零搭一个能跑通的多模式对话流，最小节点集。先照这个跑通，再往上加分支。

## 一、变量清单

在画布左侧【变量】面板建立，全部为**会话变量**（不是环境变量）。

| 变量名 | 类型 | 默认值 | 作用 |
|---|---|---|---|
| `current_mode` | String | `idle` | 状态门控，唯一决定本轮走哪条链路 |
| `session_score` | Number | `0` | 本轮累计得分 |
| `weakness_log` | String | 空 | 薄弱点累计，用分隔符拼接 |

`current_mode` 的取值只有三个，不要随意扩展：

| 取值 | 含义 | 谁能写 |
|---|---|---|
| `idle` | 自由问答 | 初始值、各闭环退出时回写 |
| `practice` | 陪练中 | 进入陪练时写入，结束标记命中时回写 `idle` |
| `quiz` | 训练中 | 进入训练时写入，达标或题量满时回写 `idle` |

## 二、节点清单与连线顺序

```text
【开始】
   │
   ▼
【条件分支：主控状态机】          ← 唯一入口，所有请求先过这里
   ├─ IF  current_mode = practice ──→ 【LLM：陪练对局与判卷】
   │                                     │
   │                                     ▼
   │                                 【条件分支：是否结束】
   │                                     ├─ 含 [SUCCESS]/[FAIL] ──→ 【变量赋值：回写 idle】→【直接回复：结算】
   │                                     └─ 未含 ────────────────→ 【直接回复：对局续接】
   │
   ├─ ELIF current_mode = quiz ─────→ 【LLM：出题与判卷】
   │                                     │
   │                                     ▼
   │                                 【条件分支：是否达标】
   │                                     ├─ 含 [END] ──→ 【变量赋值：回写 idle】→【直接回复：成绩单】
   │                                     └─ 未含 ─────→ 【直接回复：下一题】
   │
   └─ ELSE（idle）──────────────────→ 【问题分类器：意图路由】
                                         ├─ 知识答疑 ──→【知识检索】→【LLM：答疑】→【直接回复】
                                         ├─ 开启陪练 ──→【LLM：问画像】→【变量赋值：practice】→【直接回复】
                                         ├─ 开启训练 ──→【LLM：问主题】→【变量赋值：quiz】→【直接回复】
                                         └─ 兜底 ─────→【直接回复：引导语】
```

## 三、逐节点配置要点

**1. 开始节点**
只留一个 `query` 输入，不要在这里做任何参数提取。

**2. 条件分支：主控状态机**
- 分支数量 = 3（practice / quiz / 其余）
- 判断变量必须引用会话变量 `current_mode`，不要引用上一节点的输出
- 这是整条流唯一读 `current_mode` 的地方

**3. 问题分类器**
- 只在 `ELSE` 出口之下，绝不能出现在状态机之前
- 类目描述写具体例句，不要写抽象概括
- 兜底类目必须单独存在，不要与"打招呼"合并

**4. 各闭环 LLM**
- 系统提示词里写死结束标记的产出条件与位置
- 标记必须单独成行，且只在结论句出现
- 承载判卷的模型不要用轻量模型，标记会漏

**5. 变量赋值节点**
- 进入闭环：用**覆盖**模式，值选常量 `practice`
- 退出闭环：用**覆盖**模式，值选常量 `idle`
- 累计类变量（得分、薄弱点）无法用赋值节点追加，改用模板转换节点拼接

**6. 直接回复**
- 富媒体信令必须单独成行，前后不留其他文字
- 预览区显示为代码属正常，前端可解析

## 四、跑通验证顺序

按这个顺序验，每一步都要过：

1. **状态门控**：进入陪练后，随口问一句业务问题，确认没有触发知识检索（回复下方不应出现 RAG 标签）
2. **闭环退出**：触发结束标记，确认能回到自由问答，且 `current_mode` 已回写 `idle`
3. **重入**：退出后再次进入陪练，确认能正常进入，不是卡在上一次的状态
4. **兜底**：输入一句完全无关的话，确认走兜底而不是被某个业务分支接走
5. **累计变量**：跑两轮后检查 `weakness_log` 是否真的累积了内容，不是被覆盖

## 五、常见走偏

| 症状 | 位置 |
|---|---|
| 进入场景后仍触发知识库 | 状态机没放在开始节点之后第一位 |
| 场景永远退不出 | 结束标记没产出，或退出分支没回写 `idle` |
| 退出后再进不去 | 进入分支用了"设置"模式，常量没写进去 |
| 无关问题被闲聊接走 | 兜底与打招呼合并成一个类目 |
| 薄弱点日志只剩最后一条 | 用变量赋值做了追加，应该用模板转换 |
