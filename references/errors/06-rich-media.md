# 富媒体组件

覆盖症状：前端不显示、显示成代码、信令格式错、表单解析失败

条目 105–130（共 26 条）

### 105. 富媒体在预览区显示成一段代码，屏幕上不弹组件

- **现象**：Dify 预览里出现 `widget_pic_start:{__image_url:...}:widget_pic_end` 原文，大屏前端没有任何反应；研发说正则匹配不到。
- **原因**：链路走了 Agent 模式，或信令后又挂了一个 LLM 做「润色」。模型把信令当普通文本再加工一轮，加粗、换行、补解释、改标记名，前端正则失配。
- **解法**：改用**对话流（Chatflow）**，由【直接回复】节点直出。富媒体链路只保留三段：LLM 提取结构化数据 → 代码执行拼信令 → 直接回复输出。信令下游不接任何模型节点。

### 106. 预览区显示代码，但研发确认能正常取到——这是正常现象

- **现象**：带签名的图片 URL 有 200+ 字符，预览窗口折成多行，`}:widget_pic_end` 被挤到最底部；Dify 还把紧贴 URL 的结束标记染成蓝色链接，看起来像丢了。
- **原因**：Dify 原生聊天框不认识这套自研协议，只做纯文本渲染。
- **解法**：不要以「预览区没渲染」判断失败。复制预览区文本，检查 `:widget_pic_end` 是否存在；判断标准是研发正则能否从 `widget_pic_start:` 匹配到 `:widget_pic_end`。

### 107. 组件不弹窗，检查发现信令和台词挤在同一行

- **现象**：`您好，为您找到以下内容widget_pic_start:{...}:widget_pic_end` 连成一行，前端不识别。
- **原因**：代码节点拼输出时用了 `+` 而没加换行，或【直接回复】里把变量紧贴在文字后面。
- **解法**：台词与信令之间必须有换行：`final_output = f"{speech_text}\n{widget_str}"`，并保持信令「单独一行」。

### 108. 链接组件整段不显示，或标题和网址串在一起

- **现象**：`widget_link_start:{__link_title:某科技公司官方网站,__link_url:https://example.com}:widget_link_end` 前端解析失败。
- **原因**：链接组件的分隔符是**一个英文半角空格**，被写成了逗号。
- **解法**：改回 `widget_link_start:{__link_title:某科技公司官方网站 __link_url:https://example.com}:widget_link_end`。逗号只用于地图和表单。

### 109. 地图卡片不弹，或起终点全空

- **现象**：`widget_map_start:{__start_text:上海桂林路 __end_text:上海外滩 __type:driving}:widget_map_end` 无效。
- **原因**：地图组件分隔符是英文半角逗号，被写成了空格；同时参数名 `__end_text` 前的逗号丢失。
- **解法**：严格按 `widget_map_start:{__start_text:上海市桂林路,__end_text:上海市外滩,__type:riding}:widget_map_end` 拼，三个参数两两之间都是 `,`。

### 110. 地图 `__type` 传了中文，前端报错

- **现象**：前端收到 `__type:骑车`，组件渲染异常。
- **原因**：`__type` 只接受 `driving` / `walking` / `riding` / `transfer` 四个英文枚举，中文口语未映射。
- **解法**：在提取节点的 SYSTEM 提示词里做映射（自驾/开车/打车 → `driving`，步行/走路 → `walking`，骑行/骑车/单车 → `riding`，公交/地铁 → `transfer`，未明说默认 `driving`），代码里再做一次白名单校验，非法值回落 `driving`。

### 111. 地图定位到外地同名地点

- **现象**：用户说「去人民广场」，屏幕路线跨省；或「去万达广场」定到了别的区。
- **原因**：只传地名不传城市，前端高德 SDK 用设备默认定位城市挑最热门匹配项。重名是真实风险：「人民广场」全国几乎每个城市都有，上海还有「奉贤人民广场」；「万达广场」仅上海就有 8 座。
- **解法**：提示词强制补齐城市前缀（`上海市人民广场`），不传经纬度。只有业务要求精确到门牌、且前端具备经纬度渲染能力时，才接高德 MCP 拿官方纠偏坐标。

### 112. 地图定位到太平洋或海里

- **现象**：起终点坐标明显错误，路线图指向无人区。
- **原因**：让模型自己估经纬度，模型编造数值。
- **解法**：坐标只能来自地理编码工具（高德 MCP）的真实返回，禁止由 LLM 生成经纬度。

### 113. 静态地图返回 401 / INVALID_USER_KEY

- **现象**：`https://restapi.amap.com/v3/staticmap?...&key=xxx` 返回错误码，图片不显示。
- **原因**：用了「Web 端 JS API」类型的 Key。
- **解法**：高德 Key 的**服务平台必须选「Web 服务」**，不能是 JS API。

### 114. 手机上看地图时被拉起高德 App

- **现象**：本该在大屏内嵌窗口显示，结果跳转到手机 App。
- **原因**：`uri.amap.com` 的 `callnative` 参数没设或不为 0。
- **解法**：URL 里固定写 `&callnative=0`，强制网页内打开。

### 115. Web URI 里中文地名乱码

- **现象**：`from=上海市桂林路` 直接拼进 URL，前端拿到乱码。
- **原因**：中文未做 URL 编码。
- **解法**：`urllib.parse.quote()` 后再拼：`enc_origin_name = urllib.parse.quote(origin_name)`。

### 116. 代码节点报 SSL 证书错误

- **现象**：`urllib.error.URLError: <urlopen error [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed...>`
- **原因**：代码里用 `urllib.request` 下载图片字节流。Dify 代码节点跑在精简 Docker 沙箱，缺根证书。
- **解法**：不要下载字节流，只把 URL 拎出来返回：`return {"image_url": data[0].get("url", "")}`。生图插件返回的已是可直接访问的公网 URL，带签名参数，无需二次处理。

### 117. 图片位置显示乱码文字，图片不显示

- **现象**：屏幕上是 `![图片]({'type': 'image', 'transfer_method': 'local_file'...})` 这类乱码。
- **原因**：把 Dify 的图片对象字典塞进了 Markdown 括号，括号里必须是 URL 字符串。
- **解法**：只放 URL。用 `widget_pic_start:{__image_url:{{代码执行.image_url}}}:widget_pic_end`。

### 118. 图片组件不显示，检查发现插错了变量

- **现象**：信令里 `__image_url` 的值是网页标题文字。
- **原因**：把 `page_title` 插进了 `__image_url`。图片组件只认图片 URL 变量。
- **解法**：`__image_url` 后只插图片 URL 变量；同一分支里既有标题又有图片时，分开登记变量，逐项核对。

### 119. 代码节点报 `'list' object has no attribute 'get'`

- **现象**：高德 MCP 返回后代码崩。
- **原因**：`paths` 是列表，直接 `.get()` 调用失败。
- **解法**：先判类型取首元素：`path_info = paths_list[0] if isinstance(paths_list, list) and paths_list else (paths_list if isinstance(paths_list, dict) else {})`，再 `.get("distance", 15000)` 兜默认值。

### 120. 代码节点报 `Expecting value: line 1 column 1`

- **现象**：JSON 解析失败，字段全部回落「未提供」。
- **原因**：模型输出带了前缀标记或客套话（如 `[ALL_COMPLETE]\n{...}`），整段 `json.loads` 直接崩，代码落进 `except` 静默分支。
- **解法**：先括号切片再解析：`m = re.search(r'(\{[\s\S]*\})', text)`，`json.loads(m.group(1))`。`[\s\S]` 覆盖换行，贪婪匹配能容忍尾部多余字符。

### 121. 页面全白，一个多余的字母

- **现象**：前端弹窗打开后整页空白，没有任何报错。
- **原因**：URL 拼错，曾出现 `"page_url": "hhttps://www.shairport.com/..."`。
- **解法**：拼 URL 前统一过前缀校验：`if not page_url.startswith(("http://", "https://")): page_url = "https://" + page_url.lstrip("/")`。

### 122. 表单屏幕显示的还是旧字段

- **现象**：把「身份证号」换成「所属企业」，屏幕上仍显示身份证号，或该行空白。
- **原因**：只改了 LLM 提示词，代码节点取值、`form_payload.fields`、正则兜底没同步。
- **解法**：四处一起改——① LLM SYSTEM 提示词输出键名 ② 代码取值行 `data.get("company") or data.get("所属企业") or "未提供"` ③ `form_payload.fields` 的 `label`/`key`/`value` ④ 正则兜底规则。`key` 变更需同步告知前端；【直接回复】和 `build_widget_form` 不用改。

### 123. 表单提交后下游节点拿不到数据

- **现象**：用户点了确认，下一轮发飞书/写库/条件判断全是空值。
- **原因**：前端回传的是中文句式文本 `【我已确认以下信息】访客姓名:未提供，手机号码:未提供，...`，下游仍按 JSON 解析。
- **解法**：按中文句式解析——固定前缀 `【我已确认以下信息】`，字段间中文逗号 `，`，字段名与值之间英文冒号 `:`。取不到时用字段级正则兜底，如 `re.search(r'(1[3-9]\d{9})', text)` 取手机号。

### 124. 出错时字段全「未提供」，查不到任何线索

- **现象**：所有字段同时回落默认值，日志无异常。
- **原因**：`try/except` 把业务拼装一起包住了，异常被吞。
- **解法**：`try/except` 只包解析动作，不包拼装；解析失败要有显式日志，不要静默回落。

### 125. 【直接回复】里选不到代码节点的输出变量

- **现象**：变量选择列表里没有 `result`，或插入后为空。
- **原因**：代码 `return {"result": final_output}`，但界面输出变量没登记，或名字不一致。
- **解法**：在代码节点的输出变量区手动点 `+` 登记 `result`（String），名称与 `return` 的键完全一致。需要多个变量时逐个登记，不能只写在 `return` 里。

### 126. 数字人念到一半中断，或客户端卡死

- **现象**：生图类任务中，数字人说完开场就断，屏幕长时间无响应。
- **原因**：生图耗时 4~8 秒，期间无语音输出，客户端保活心跳判定任务中断。
- **解法**：拆音画双轨——声音轨用低首字延迟模型先出 80~120 字纯文本（禁 Markdown、禁括号动作描写），视觉轨后台生图，末端【直接回复 2】只放图片信令。图片晚到正常，收到就弹，收不到不弹，不做同步阻塞。

### 127. 台词没念完屏幕就跳走，声音被掐断

- **现象**：页面切换时数字人声音突然中断。
- **原因**：`<ue4event>` 放在了 `<break time="1000ms"/>` 之前，事件在台词中途触发。
- **解法**：`<break>` 必须在 `<ue4event>` **之前**，先静音 1 秒留出反应时间，再抛跳转事件。

### 128. 跳转事件里做了不存在的动作

- **现象**：SSML 里 `<action_semantic>` 的动作没有执行，或整个事件被忽略。
- **原因**：动作名不是动作库里实际存在的预置动作。
- **解法**：`point_screen` 等需替换为动作库真实名称，如 `guide_right`、`point_forward`；先在动作库确认存在再写入 SSML。

### 129. 转场动画不生效

- **现象**：页面直接切换，没有淡入效果。
- **原因**：`<transition>` 取值不在支持列表，或前端未实现该动画。
- **解法**：取值限定 `fade_in`（默认）/ `slide_left` / `slide_up` / `none` / `instant`。不加此参数不影响跳转逻辑，前端未实现动画时整行删除。

### 130. 两套信令混用，前端只认其中一套

- **现象**：地图用 `widget_map_start:`、表单用 `:::STRUCTURED_FORM_CARD`，其中一个不显示。
- **原因**：`widget_*` 单行扁平协议与 `:::` JSON 卡片协议是两套实现，前端只解析自己实现的那套。
- **解法**：开工前先与研发确认当前实现，同一套对话流只用一套协议，不混用。
