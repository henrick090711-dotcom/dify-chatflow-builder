# 提示词设计

覆盖症状：答非所问、反复反问、提取出 UNKNOWN、标记透传

条目 29–55（共 27 条）

---

按现象查。每条给现象、提示词层面的根因、具体改法。

---

### 29. 客户模拟每轮重复开场白，进不了多轮

- **现象**：用户回一句"请问您的预算是多少"，模型又生成一段全新的开场白，画像也不对。
- **原因**：开场白节点与多轮对话共用同一个 LLM 节点，节点提示词里是"直接说出你进店后的第一句话"。模型收到新输入后只能再执行一次"说第一句话"。
- **解法**：拆成两个节点。开场白节点只负责第一句；多轮节点提示词显式写 `不要自己跳戏，不要重复开场白`，并写 `对销售员刚才的话语做出自然的回答`。同时给多轮节点打开记忆开关。

### 30. 模型记不住上一轮，每轮把用户当新客户

- **现象**：多轮对练中模型反复重新自我介绍、重新开场。
- **原因**：LLM 节点右侧的【记忆】开关处于关闭状态，对话历史不传入。
- **解法**：打开记忆开关，设为默认对话历史。凡是跨轮对话的节点（客户模拟、判卷考官、前台登记）都必须打开。

### 31. 判卷考官点评完就闭嘴，不出下一题

- **现象**：考官点评结尾说"需要继续开展训练"，然后没有下一题，用户被迫输入"好的，那接着训练"。
- **原因**：提示词只写了"判断是否应该结束本次训练"，没写不结束时该做什么。模型把"判断"执行完就结束输出。
- **解法**：把任务写成两步，第二步必须给动作。

```text
结局 A（继续考核）：如果你认为还需要再考一题，请在点评结束后，换行，【直接向销售提出关于该业务的下一个新问题】！严禁等用户说"继续"，你必须主动发问！严禁在回复中出现 [END] 字样！
```

### 32. 用户的过渡句被判卷机器当成考卷批改

- **现象**：用户输入"好的，那接着训练"，考官回"你仅回应了'好的'，未体现业务知识，准确率 0%"。
- **原因**：判卷节点没有场景识别，只要收到文字就当答题。上游又没让考官主动出题，用户必然产生过渡句。
- **解法**：根治办法是让考官在点评后立刻出题（见上一条），用户下一句自然就是业务回答，不再产生过渡句。

### 33. 一边输出新问题，一边输出 [END]

- **现象**：模型既问了一道新题，又在末尾带上 [END]，条件分支把它判定为结束。
- **原因**：提示词里同时存在"继续出题"和"输出 [END]"两条并列指令，模型两边都执行以求保险。缺少互斥约束。
- **解法**：改成 A/B 二选一，且每条都带负面约束。

```text
结局 A（继续训练）：如果你认为还需要再考一题，请直接提出下一个新问题。严禁在回复的任何地方出现 [END] 字样！
结局 B（结束训练）：如果已经问够了3个问题，或者用户回答得非常完美/极其糟糕，请判定为结束。请在点评的最后一行，单独换行输出 [END]。严禁再提出任何新问题！
```

### 34. 提示词里手敲变量名，模型把变量名念出来

- **现象**：输出"未体现出对 quiz_topic 相关的掌握情况"，变量没有被替换成"5G业务"。
- **原因**：`{{quiz_topic}}` 是手动敲进去的纯文本，不是变量引用块，模型把它当字面内容。
- **解法**：清空该段，点击提示词框右上角 `{x}`，从列表选择会话变量，插入成带底色的变量气泡。检查方法：提示词里所有变量都应是气泡，不是文本。

### 35. [END] 标记直接显示在用户界面上

- **现象**：用户看到回复末尾多出 `[END]` 五个字母。
- **原因**：标记由 LLM 输出，Dify 默认节点无法在文本中擦除，直接透传给前端。
- **解法**：二选一。一是下游用条件分支消费标记后只输出截断后的文本；二是在直接回复节点里排版隔离。

```text
{{LLM 6.text}}

━━━━━━━━━━━━━━━
本次专项训练全部结束！
您可以随时输入"生成报告"查看总体分析。
```

### 36. 信息提取输出全是 UNKNOWN / 未提供

- **现象**：访客说"我是张总，找柴教授"，三个字段全填 UNKNOWN。
- **原因**：模型根本没收到访客原话。两处接线缺失：SYSTEM 下方的 USER 消息没添加，输入框为空；或者数据放进了上下文栏但提示词里没有变量引用，系统只弹黄字"要启用上下文功能，请在提示中填写上下文变量"。
- **解法**：先清空上下文栏，再点 `+ 添加消息` 生成 USER 消息，在 USER 里用 `{x}` 插入 `sys.query` 气泡。改完再谈提示词。

### 37. 被访人被填成"前台工作人员"

- **现象**：访客找柴教授，提取结果写成"前台工作人员"。
- **原因**：小模型发生角色混淆，把自己这个前台当成被找的对象；提示词里没有排除项。
- **解法**：加一条绝对禁令 + 缺省值。

```text
1. 【被访人】：访客进门要找谁？（支持人名或职位尊称，如"柴教授"、"西南"、"王总"、"李工"）。绝对禁止填写为"前台工作人员"！如果原话完全没提找谁，写"未指定"。
```

### 38. 把"我是张总"里的张总当成被访人

- **现象**：单字段提取时，把自我介绍的名字提成要找的人。
- **原因**：提示词只写"提取人名"，没区分"我是谁"和"我找谁"，也没给范例。
- **解法**：写规则 + 给范例。

```text
【核心规则】：
1. 区分"我是谁"和"我找谁"：不要提取自我介绍的名字，只提取被找的人名！
2. 只输出被找员工的纯名字，绝对禁止输出任何标点符号、前缀或废话！
3. 如果原话里完全没有提想找谁，只输出：UNKNOWN

【参考范例】：
输入："我是瑞航，我来找你们公司贺恒垚开会"
输出：贺恒垚
```

### 39. 职位尊称识别不出来，非要全名

- **现象**：只有"柴教授""王总""李工"这类称呼时，模型判为未提供姓名。
- **原因**：提示词未声明哪些形式算合法称呼。
- **解法**：在字段说明里直接列举：`支持人名或职位尊称，如"柴教授"、"西南"、"王总"、"李工"`。

### 40. 打招呼也回"知识库暂未收录"

- **现象**：用户说"你好"，模型回"抱歉，目前的知识库中暂未收录该问题的相关信息"。
- **原因**：只有一条兜底红线，没有场景分流。任何输入先撞上"知识库无记录就回兜底话术"。
- **解法**：加场景 A（打招呼），写死欢迎语并声明豁免兜底红线。

```text
## 场景 A：用户纯粹打招呼（如"你好"、"在吗"、"哈喽"等）
- 执行规则：热情、口语化地迎接。
- 输出格式："您好！我是数字医生童晓嘉。请问今天有什么关于儿童青少年健康，或我院门诊指引的问题需要我帮您解答吗？"
- 豁免红线：此场景【绝对禁止】附带"以上内容仅供参考"的免责声明。
```

### 41. 无关提问（"周杰伦是谁"）也回欢迎语

- **现象**：用户问完全无关的问题，模型输出一长串自我介绍，像没听懂。
- **原因**：无关闲聊和打招呼共用同一条固定回复。
- **解法**：拆出场景 B，写死礼貌回绝，并声明禁查知识库、禁附免责声明。

```text
## 场景 B：用户提出与医疗/医院完全无关的提问（如"周杰伦是谁"、"今天天气"等）
- 执行规则：高情商、礼貌地回绝。
- 输出格式："您好！我是五健数字医生童晓嘉。我只提供儿童健康科普和就诊指引服务，无法回答与此无关的问题哦。请问有什么我可以帮您？"
- 豁免红线：此场景【绝对禁止】去查知识库，【绝对禁止】附带免责声明。
```

### 42. 用户骂人时机械复读官方话术

- **现象**：用户输入"你真垃圾""我是个废物"，模型回"您好！我是童晓嘉……请问有什么可以帮您"，逐字不变。
- **原因**：负面情绪被误判进"无关提问"场景，而该场景是写死话术，无法变化。
- **解法**：新增场景 E，只给结构不给话术，让每轮措辞变化。

```text
## 场景 E：用户表现出负面情绪、吐槽、责骂或侮辱
- 执行规则：保持极其温和、谦逊、有同理心的态度，进行温柔的抚慰与诚恳道歉。绝对禁止生硬反驳！绝对禁止死板复读！
- 输出规范：
  1. 第一句话必须是诚恳道歉的短句（10字以内，如"真的非常抱歉。"）。
  2. 大方承认自己还在努力学习和成长，并温柔地把话题引回到服务上。
  3. 【绝对禁止】在此场景输出"以上内容仅供参考"。
  4. 字数严格控制在 100 字以内。
```

### 43. AI 主动反问，把用户带进检索黑洞

- **现象**：模型答完"眼科在四楼"后加一句"需要了解专家详细介绍吗"，用户回"需要"，系统把"需要"当检索词，知识库返回空，模型立刻输出兜底话术。
- **原因**：提示词没有禁止反问。模型习惯性加客套引导，引导语本身没有检索价值。
- **解法**：加禁反问红线，要求回答完立即收尾。

```text
【绝对禁止主动反问】（核心体验红线）：
- 在任何场景的回答结尾，你绝对禁止主动向用户提出反问或引导（如"您需要了解排班吗？"、"需要进一步指引吗？"）。
- 你必须直接且客观地结束你的回答，把提问的权利 100% 交还给用户，保持绝对被动的解答状态。
```

### 44. 整版人设塞进专家节点，模型拒绝回答排班

- **现象**：专家查询节点被问"今天有哪些专家"时，拒绝回答或绕开问题。
- **原因**：整版人设里有一条"绝对禁止提及任何具体的医生姓名或简介"，与该节点任务直接冲突。模型在冲突中选择遵守禁令。
- **解法**：按节点拆分人设。专家节点删除"禁提医生"这条，改为"信息来源唯一性"：`你回答的排班、医生名字、科室地点，【必须且只能】严格源于下方的[HIS/数据]。绝对禁止自己胡编乱造。`

### 45. 科普节点误吐挂号链接

- **现象**：用户问"近视了怎么办"，回复里混进挂号链接。
- **原因**：把挂号链接分流逻辑复制进了科普节点。提示词过长、干扰过多，模型回答科普时分心，顺手把链接一起输出。
- **解法**：链接逻辑只留在挂号分发节点。科普节点加 `【防过度推销】绝对禁止在科普中主动提及"扫码"、"挂号"等字眼`，并删掉该节点里所有链接文本。

### 46. 播报刷屏，把十几个日期全列出来

- **现象**：用户问眼科门诊，模型把接口返回的十几天排班逐条列出，回复超长。
- **原因**：提示词只说"播报排班号源"，没有阈值也没有简化方式，模型按资料全量复述。
- **解法**：给可数阈值 + 现成替代话术。

```text
【防刷屏红线】：如果接口数据中返回的排班日期超过了 3 天，你【绝对禁止】把日期一个个列出来！你【必须】进行以下高度概括简化："目前每日均有普通医生出诊，上午和下午均有号源，建议您提前预约。"
```

### 47. 问位置却播排班，所答非所问

- **现象**：用户问"儿科急诊在哪"，模型回了排班、号源、导医台一堆信息。
- **原因**：提示词没把用户原话放进去做口径对齐，模型按"资料里有什么就播什么"行事。
- **解法**：在提示词顶部引用 `{{#sys.query#}}`，并写死所答即所问的分支。

```text
【最高红线 1】所答即所问，绝不废话：
- 如果用户只问"在哪里/位置/几楼"，你【必须且只能】回答【就诊指引】里的地点和院区。由于用户没问挂号排班，你【绝对禁止】提及"暂无排班、号源、现场导医台"等任何多余的废话！
- 如果用户问"什么时候有号/排班"，你再播报【排班号源】。
```

### 48. 首句 10 字限制导致模型背诵自我介绍

- **现象**：每轮回复第一句都是"童晓嘉是五健数字医生"，内容呆板。
- **原因**：限制"第一句 10 字以内"却没给示范，模型发现最稳妥的十字句就是自我介绍。
- **解法**：在字数限制后补一条禁令和两个示范。

```text
- 第一句话必须是短句（10字以内，结尾有标点。严禁直接背诵自我介绍！例如"视力保护很重要。"或"针对您的问题："）。
```

### 49. 免责声明无条件附加

- **现象**：打招呼、无关提问、兜底话术后面都挂着"以上内容仅供参考"。
- **原因**：免责话术写成"必须统一在结尾附上"，没有场景豁免，与兜底话术叠加后字数超限。
- **解法**：在每条场景规则里写明豁免；同时在兜底红线里写明豁免首句限制。

```text
（注：遇到此情况时，直接输出上述整句，豁免下方"第一句10字以内"的限制）
```

### 50. 输出 Markdown、数字列表、引用角标、括号动作

- **现象**：语音播报把"星号""1.""[1]""（微笑着说）"都念出来。
- **原因**：提示词缺格式红线，模型默认使用 Markdown 组织信息。
- **解法**：播报节点四条格式红线必须齐全。

```text
绝对纯文本禁令：最终输出【绝对禁止】包含任何形式的 Markdown 标记符号（如加粗 **、标题 #、列表等）。
去列表化处理：严禁使用"1. 2. 3."等数字序号列点。必须将所有内容转化为使用"首先、其次、另外"连接的连贯自然段落。
引用标识彻底抹除：回复中【绝对禁止】出现类似 [1]、[2] 的引用角标或文档后缀名。
禁止括号描写：严禁在回复中使用括号（）或 [] 描写动作、神态。
```

### 51. 中文填进 HTTP header 直接报 ascii 编码错

- **现象**：接口测试时报 `'ascii' codec can't encode characters in position 0-6: ordinal not in range(128)`。
- **原因**：参数位置是 `in: header`，请求头只接受 ASCII。填了 7 个汉字"上海飞北京航班"，底层编码当场崩溃。
- **解法**：转换节点提示词写死 ASCII 红线，并把中文归一化交给字典。

```text
X-JSON-Path 将作为 HTTP 请求头发送：整个表达式只允许 ASCII 字符，禁止中文、换行和 Unicode 字符。
```

### 52. 参数转换节点输出一段解释，下游解析失败

- **现象**：本该只输出 `json_path` 字符串，模型附赠"根据您的要求，我为您生成如下查询条件……"。
- **原因**：提示词写成了"助手"角色，模型默认要解释。没关掉意图识别、追问、回答、解释这四项能力。
- **解法**：写成"转换器"，四句"无需"写全，并锁定输出结构。

```text
你是浦东机场 T1/T2 出港航班数据库的查询参数转换器。上游 Agent 已经判断需要查询航班，并将需要查询的条件作为输入。你只需把这些条件转换成 JSONBin 的 X-JSON-Path 参数。无需识别意图、无需追问、无需回答航班信息、无需解释。
只通过 Dify 结构化输出返回一个对象，包含唯一字段 json_path（字符串）。不要输出代码块或其他字段。
```

### 53. 用户说"今天"查不出任何数据

- **现象**：查询航班返回空数组，换"明天"也一样。
- **原因**：库内只有 2026-10-09 至 2026-10-12 的数据，提示词里还写着"用户说今天/明天就输出 `__NO_MATCH__`"，没有日期默认映射。
- **解法**：写死日期映射，并给"未指定日期"默认分支。

```text
# 日期默认映射规则
- 当用户输入"今天"、"今日"或询问某地航班未指定日期时，默认映射为 flight_date=="2026-10-09"。
- 当用户输入"明天"、"明日"时，默认映射为 flight_date=="2026-10-10"。
- 若用户直接通过具体航班号查询，则只按 flight_no 过滤，不加日期限制！
```

### 54. 用户换一种说法就查不到，字段值对不上

- **现象**：用户问"东航""国航"，生成的 JSONPath 里塞了中文航司名，接口返回空。
- **原因**：提示词没给归一化字典，模型自己翻译，字段值不在库内枚举范围。
- **解法**：给字段白名单 + 逐条字典，并禁止使用中文值字段。

```text
# 可查询字段白名单
flight_no、flight_date、airline_code、destination_city_key、destination_airport_code、terminal、flight_type_key、status_key。
不得使用 destination_city / status / flight_type 等包含中文值的字段。只允许双引号、==、&&。

# 归一化字典
中国东方航空/东航=MU；中国国际航空/国航=CA；中国南方航空/南航=CZ；吉祥航空/吉祥=HO。
```

### 55. 上下文栏有数据，模型仍说没收到

- **现象**：上下文栏挂了用户输入变量，模型输出 UNKNOWN，页面弹黄字提示。
- **原因**：变量只放进上下文栏，SYSTEM 提示词里没有用 `{x}` 引用，模型看不到内容。
- **解法**：三处对齐检查。上下文只放参考资料（知识库召回、接口返回、上游输出），用户原话放 USER 消息，SYSTEM 里用变量气泡引用需要读取的数据。提取类、转换类节点上下文栏保持为空。
