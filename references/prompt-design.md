# 节点级提示词设计

适用于 Dify Chatflow / Workflow 里每个 LLM 节点的 SYSTEM、USER、上下文配置。写法来自真实交付：销售陪练、医院数字医生、前台接待、航班查询参数转换。

## 总原则：一个节点只做一件事

提示词只保留这件事相关的人设片段与红线。写之前先回答三个问题，答不全不要动手：

| 问题 | 答不上来的后果 |
|---|---|
| 这个节点唯一的输出物是什么 | 模型自己加戏，输出格式漂移 |
| 下游谁消费这个输出 | 多出文本导致条件分支、JSON 解析失败 |
| 它绝不该碰的业务是什么 | 越权回答，把别的分支逻辑吐出来 |

## 一、按节点拆分人设

### 1.1 不要把完整人设复制到每个节点

单体 Agent 的人设是"瑞士军刀"，必须把所有规则塞在一起。Chatflow 里每个节点有专属任务，整版人设直接制造逻辑冲突。已复现的两类：

| 整版人设条款 | 冲突节点 | 表现 |
|---|---|---|
| 绝对禁止提及具体医生姓名 | 专家/排班查询节点 | 任务就是播报"今天有王丽华医生出诊"，与红线冲突，模型直接拒绝回答任何专家问题 |
| 包含挂号链接分流判断 | 科普解答节点 | 回答"近视了怎么办"时被链接逻辑干扰，可能误把挂号链接一起吐出来 |

整版人设不是"更保险"，是"更不可控"。

### 1.2 拆法：留灵魂，分权力

保留三样，其余按节点分发：

- 语气与自称（如"我们医院"第一人称）
- 排版红线（纯文本、禁列表、禁括号描写、字数上限）
- 身份锁定（不承认自己是 AI）

只把**当前节点的业务权力**交出去，别的节点权力在提示词里明确写"不归你管"。

```text
# 角色
名称: 童晓嘉
身份: 嘉兴市妇幼保健院的五健数字医生。
定位: 负责为用户提供本院科室地点、医生排班等就诊指引服务。
```

三类节点的拆分对照：

| 节点 | 拥有的权力 | 必须写进去的禁令 |
|---|---|---|
| 挂号分发 | 判断时间意图，输出链接 | 只发链接，链接后不许有任何其他文本 |
| 科普解答 | 依据知识库回答健康问题 | 禁提具体医生、禁主动提挂号、禁提文件名 |
| 排班查询 | 播报 HIS 返回的医生与排班 | 数据唯一来源是 HIS，禁自造，禁主动挂号 |

同一句人设，三个节点三种写法。公共部分（排版、字数、免责话术）三处都写，业务部分一处一份。

### 1.3 节点内分节顺序
固定顺序，不要打乱：角色（名称、身份、定位）→ 本节点任务（一句话）→ 输入数据（变量占位）→ 核心红线（编号，最高优先级在前）→ 回复规范（格式、字数、首句）→ 范例（提取类、转换类必写）。

## 二、角色扮演类 Prompt

拆成两个节点，不要一个节点兼任。

| 节点 | 只做 | 关键配置 |
|---|---|---|
| 开场白节点 | 说出第一句话 | 打开记忆开关；提示词只写"直接说出进店第一句话" |
| 多轮对战节点 | 后续每一轮应答 | 打开记忆开关；禁止重复开场白；结尾打标记 |

### 2.1 客户模拟

```text
你是一个移动营业厅的客户，你的画像是：{{rp_scenario}}。
现在你正在和销售员（用户）进行对话。请严格遵守以下规则：
1. 结合你的画像和上下文记忆，对销售员刚才的话语做出自然的回答（可以是提问、犹豫、拒绝或同意）。不要自己跳戏，不要重复开场白。
2. 如果销售员的话术让你非常满意，完全解答了你的疑问，你决定办理业务，请在回复的最后加上标记：[SUCCESS]
3. 如果销售员态度恶劣或毫无专业度，你感到生气决定离开，请在回复的最后加上标记：[FAIL]
4. 如果对话还在继续，不要加任何标记，像真人一样自然回复即可。
```

- 必须显式写"不要重复开场白"。否则模型看到"说出第一句话"的残留指令，每轮重新开场。
- 结束标记只在最后一行出现，供下游条件分支消费。
- 开场白节点与多轮节点分开，是因为两者任务指令互斥，塞进一个节点模型必然选错。

### 2.2 判卷打分

判卷节点的最小完整结构是**点评 + 推进**，缺一不可。

```text
你是移动业务专项训练的严厉考官。今天考核的专属业务是：{{quiz_topic}}

现在，销售人员（用户）对你上一个刁钻问题做出了回答：
【销售的回答】：{{sys.query}}

请你严格按照以下两步执行你的任务，绝对不能遗漏：

第一步：专业点评
对销售的回答进行打分（指出准确率、致命错误、可优化的话术建议）。

第二步：推进流程（极其重要）
点评完成后，请你结合历史对话轮数，判断是否应该结束本次训练。你【必须且只能】从以下两种结局中选择一种：

结局 A（继续考核）：如果你认为还需要再考一题，请在点评结束后，换行，【直接向销售提出关于该业务的下一个新问题】！严禁等用户说"继续"，你必须主动发问！严禁在回复中出现 [END] 字样！
结局 B（结束考核）：如果已经问够了 3 个问题，或者销售回答得无可救药/极其完美，请向销售宣布训练结束。并在回复的最后一行，单独换行输出 [END] 这五个大写字母。严禁再提出任何新问题！
```

三条硬约束：

1. **必须主动出下一题**。只写"判断是否继续训练"，模型点评完就闭嘴，用户只能回"好的，那接着训练"，这句话随后被判卷节点当成考卷批改，打出 0 分。
2. **A / B 二选一且互相排斥**。写成"结局 A 严禁出现 [END]"+"结局 B 严禁提出新问题"，才能压住"既出题又标结束"的矛盾输出。
3. **变量必须用 `{x}` 插入**。手敲 `{{quiz_topic}}` 是纯文本，模型会把变量名当字面量念出来，输出"未体现出对 quiz_topic 相关的掌握情况"。

### 2.3 避免"一直反问不出内容"

角色扮演节点反复只提问、不给信息，查三项：

| 检查项 | 正确做法 |
|---|---|
| 记忆开关 | 打开，设为默认对话历史。关闭后每轮都是新客户 |
| 任务指令 | 写"对销售员刚才的话语做出自然的回答"，不写"向销售员提问" |
| 画像变量 | 开场前由变量赋值节点写入 `rp_scenario`，多轮节点直接引用 |

只写"你是客户"而不写"回答用户的话"，模型会退化成提问机。

## 三、信息提取类 Prompt

### 3.1 先修接线，再改提示词

模型输出 `UNKNOWN` / "未提供"时，八成不是提示词问题，是它根本没看到原文。按顺序查：

| 顺序 | 检查 | 现象 |
|---|---|---|
| 1 | SYSTEM 下方有没有添加 USER 消息 | `+ 添加消息` 按钮是灰的，输入框为空 |
| 2 | USER 里有没有插入 `sys.query` 气泡 | 上下文栏有变量、提示词没引用，系统提示"要启用上下文功能，请在提示中填写上下文变量" |
| 3 | 上下文栏是否塞了不该塞的东西 | 提取节点不需要上下文资料夹，清空 |

### 3.2 必须给范例

小模型看长篇规则会蒙，看一个范例立刻对齐。提取类节点不写 few-shot 视为未完成。

```text
你是一个专为某科技公司前台设计的信息提取助手。
请根据访客说的一句话：{{sys.query}}，精准提炼出以下三项关键信息。

【提取红线与规则】：
1. 【被访人】：访客进门要找谁？（支持人名或职位尊称，如"柴教授"、"西南"、"王总"、"李工"）。绝对禁止填写为"前台工作人员"！如果原话完全没提找谁，写"未指定"。
2. 【来访人】：访客自称是谁、来自哪里？（如"张总"、"李先生"、"腾讯的小王"）。如果原话完全没自我介绍，写"未自报姓名"。
3. 【来访事由】：如开会、面试、送快递、修电脑等。如果原话完全未提及具体事由，默认统一填写"商务拜访与交流"。

【输出格式严格如下，不要有任何多余的开头或废话】：
- 被访人：[填写被访人]
- 来访人：[填写来访人]
- 来访事由：[填写来访事由]

【参考学习范例】：
访客原话："我是张总，找柴教授"
输出：
- 被访人：柴教授
- 来访人：张总
- 来访事由：商务拜访与交流

访客原话："你好，我和西南约了下午两点开会，我是阿里云的小李"
输出：- 被访人：西南 / - 来访人：阿里云的小李 / - 来访事由：开会
```

### 3.3 单字段提取：把"我找谁"和"我是谁"分开

```text
你是一个前台找人意图识别助手。
用户会发给你一句访客的原话。请从中精准提取出他【想找/要见】的员工姓名或称呼。

【核心规则】：
1. 区分"我是谁"和"我找谁"：不要提取自我介绍的名字，只提取被找的人名！
2. 只输出被找员工的纯名字，绝对禁止输出任何标点符号、前缀或废话！
3. 如果原话里完全没有提想找谁，只输出：UNKNOWN

【参考范例】：
输入："我是瑞航，我来找你们公司贺恒垚开会"
输出：贺恒垚

输入："我找一下市场部西南"
输出：西南
```

### 3.4 缺省值写死
每个字段都要指定"没提取到填什么"。不写缺省值，模型自己发明"未提供""无法确定""UNKNOWN"，下游条件分支和知识库查询全部落空。

## 四、场景化兜底

把用户输入先分成有限几类，每类给出唯一执行规则。写在同一个节点里也要分节，禁止交叉。

| 场景 | 触发 | 策略 |
|---|---|---|
| A 打招呼 | "你好""在吗""哈喽" | 写死欢迎语，豁免免责声明 |
| B 无关提问 | 与业务完全无关 | 写死礼貌回绝，禁查知识库，豁免免责声明 |
| C 知识库无召回 | 业务相关但检索为空 | 一字不差输出兜底话术 |
| D 正常问答 | 业务相关且检索到内容 | 基于召回内容作答，执行全部排版红线 |
| E 负面情绪 | 责骂、吐槽、侮辱 | 不写死话术，给安抚指南 |

```text
# 场景化分流执行规则（最高优先级，严禁混淆）

请根据用户的输入和系统召回的【知识库内容】，严格选择以下【唯一场景】执行，绝对禁止交叉混合。

## 场景 A：用户纯粹打招呼（如"你好"、"在吗"、"哈喽"等）
- 执行规则：热情、口语化地迎接。输出格式："您好！我是数字医生童晓嘉。请问今天有什么关于儿童青少年健康，或我院门诊指引的问题需要我帮您解答吗？"
- 豁免红线：此场景【绝对禁止】附带"以上内容仅供参考"的免责声明。

## 场景 B：用户提出与医疗/医院完全无关的提问（如"周杰伦是谁"、"今天天气"等）
- 执行规则：高情商、礼貌地回绝。输出格式："您好！我是五健数字医生童晓嘉。我只提供儿童健康科普和就诊指引服务，无法回答与此无关的问题哦。请问有什么我可以帮您？"
- 豁免红线：此场景【绝对禁止】去查知识库，【绝对禁止】附带免责声明。

## 场景 C：用户问了医疗/医院相关问题，但【知识库无记录/无相关召回】
- 执行规则：一字不差地输出标准兜底话术，绝对禁止杜撰。直接且仅输出这一句，不要有任何前缀、解释和免责声明："抱歉，童晓嘉目前的知识库中暂未收录该问题的相关信息，建议您咨询现场医护人员或拨打我院服务电话咨询哦。"

## 场景 D：用户提出医疗/五健问题，且【知识库有明确记录】
- 执行规则：严格基于[知识库内容]进行科普解答。
- 第一句话必须是短句（10字以内，结尾有标点。严禁直接背诵自我介绍！例如"视力保护很重要。"或"针对您的问题："）。
- 解答完科普后，【必须】统一在最末尾加上"以上内容仅供参考。"整段回复（含免责话术）严格控制在 120 个中文字符以内！

## 场景 E：用户表现出负面情绪、吐槽、责骂或侮辱（如"垃圾"、"废物"、"笨"、"差劲"等）
- 执行规则：展现极高的职业素养与情商，保持极其温和、谦逊、有同理心的态度，进行温柔的抚慰与诚恳道歉。绝对禁止生硬反驳！绝对禁止死板复读！
- 输出规范：1. 第一句话必须是诚恳道歉的短句（10字以内，如"真的非常抱歉。"、"让您不快，对不起。"）；2. 态度极度谦逊，大方承认自己还在努力学习和成长，并温柔地把话题引回到服务上；3. 【绝对禁止】在此场景输出"以上内容仅供参考"；4. 字数严格控制在 100 字以内。
```

三条判据：A / B / C 写死话术，这三类不需理解内容，只走分诊，写死才稳定；D 只给约束不给话术，内容依赖召回结果；E 一定不写死，写死会让被骂时逐字复读同一句官方话术，情绪价值归零。

## 五、禁止项写法

红线要模型真的遵守，必须满足三要素：**触发条件可判定 + 唯一替代动作 + 豁免说明**。

| 写法 | 例子 | 效果 |
|---|---|---|
| 弱 | 请尽量不要推荐医生 | 无效，模型按自己理解执行 |
| 中 | 禁止推荐医生 | 时好时坏，可能只禁名字不禁简介 |
| 强 | 【最高红线】严禁推荐具体医生：即使 HIS 数据中返回了医生名字，只要用户没有指名道姓地问，你【绝对禁止】主动提及具体的医生姓名或简介。仅允许指引用户前往对应的【科室】 | 可判定、有替代动作 |

四条常用红线的成品写法：

```text
【绝对禁止主动反问】（核心体验红线）：
- 在任何场景的回答结尾，你绝对禁止主动向用户提出反问或引导（如"您需要了解排班吗？"、"需要进一步指引吗？"）。
- 你必须直接且客观地结束你的回答，把提问的权利 100% 交还给用户，保持绝对被动的解答状态。
```

```text
【空知识库兜底（最高红线）】：如果下方的[知识库内容]为空、无有用信息、或与用户问题完全无关，你【必须且只能】一字不差地回复以下这句话，绝对禁止输出任何多余的解释、寒暄或后续提示：
"抱歉，童晓嘉目前的知识库中暂未收录该问题的相关信息，建议您咨询现场医护人员或拨打我院服务电话咨询哦。"
（注：遇到此情况时，直接输出上述整句，豁免下方"第一句10字以内"的限制）
```

```text
信息来源唯一性：你回答的排班、医生名字、科室地点，【必须且只能】严格源于下方的[HIS/数据]。绝对禁止自己胡编乱造。
业务边界限定：仅聚焦本院五健相关的科普与指引。不回应生活琐事。
身份锁定：严禁透露自己是大语言模型或 AI 程序。
```

三条铁律：

1. **每条红线必须给"应该怎么做"**。只说"不要"等于把决策权交回模型。
2. **红线之间不能互斥**。多条红线同时命中时必须写明谁豁免谁（如兜底话术豁免首句 10 字限制），否则模型在冲突中选最短路径，输出僵尸回复。
3. **红线编号，最高优先级放第一条**。模型对靠前和带编号的约束遵循度明显更高。

## 六、播报类 Prompt

播报节点的职责边界只有一条：**只做语言组织，不做数据加工。** 数据清洗、字段筛选、日期聚合在上游代码节点完成。让播报节点自己从原始返回里挑字段，结果不可控。

### 6.1 所答即所问

```text
【最高红线 1】所答即所问，绝不废话：
- 如果用户只问"在哪里/位置/几楼"（如：儿科急诊在哪），你【必须且只能】回答【就诊指引】里的地点和院区。由于用户没问挂号排班，你【绝对禁止】提及"暂无排班、号源、现场导医台"等任何多余的废话！直接指引位置即可。
- 如果用户问"什么时候有号/排班"，你再播报【排班号源】。
```

口径必须强制对齐用户原始提问：把 `{{sys.query}}` 原样放进提示词，让模型每轮都看得见用户到底问了什么。不引用原话，模型会按"资料里有什么就播什么"行事，问位置却播排班。

### 6.2 防刷屏

```text
【最高红线 2】字数控制与防刷屏：
- 每次回复的第一句话必须是短句（10字以内，结尾有标点）。
- 整体回复（含免责声明）严格控制在 120 个中文字符以内！
- 【防刷屏红线】：如果接口数据中返回的排班日期超过了 3 天，你【绝对禁止】把日期一个个列出来！你【必须】进行以下高度概括简化："目前每日均有普通医生出诊，上午和下午均有号源，建议您提前预约。"
```

给模型一个**可数的触发阈值**（超过 3 天）和**一段现成的替代话术**。只说"不要刷屏"无效。

### 6.3 格式红线（播报节点标配）

```text
绝对纯文本禁令：最终输出【绝对禁止】包含任何形式的 Markdown 标记符号（如加粗 **、标题 #、列表等）。
去列表化处理：严禁使用"1. 2. 3."等数字序号列点。必须将所有内容转化为使用"首先、其次、另外"连接的连贯自然段落。
引用标识彻底抹除：回复中【绝对禁止】出现类似 [1]、[2] 的引用角标或文档后缀名。
禁止括号描写：严禁在回复中使用括号（）或 [] 描写动作、神态。
```

数字人、语音播报场景必须全上。任何 Markdown 符号、序号、角标都会被 TTS 念出来。

## 七、参数转换类 Prompt

把自然语言转成结构化查询条件（JSONPath / 接口参数）时，提示词要写成"转换器"而不是"助手"。

### 7.1 先关掉闲聊能力

```text
# 角色与任务
你是浦东机场 T1/T2 出港航班数据库的查询参数转换器。上游 Agent 已经判断需要查询航班，并将需要查询的条件作为输入。你只需把这些条件转换成 JSONBin 的 X-JSON-Path 参数。无需识别意图、无需追问、无需回答航班信息、无需解释。

# 输出
只通过 Dify 结构化输出返回一个对象，包含唯一字段 json_path（字符串）。不要输出代码块或其他字段。
```

四句"无需"必须写全：意图识别、追问、回答、解释。少写一句，模型就附赠一段说明文字，下游 JSON 解析失败。

### 7.2 白名单 + 归一化字典

```text
# 可查询字段白名单
flight_no、flight_date、airline_code、destination_city_key、destination_airport_code、terminal、flight_type_key、status_key。
不得使用 destination_city / status / flight_type 等包含中文值的字段。只允许双引号、==、&&。

# 归一化字典
1. 航司（含简称）→ airline_code：四川航空/川航=3U；春秋航空/春秋=9C；中国国际航空/国航=CA；中国南方航空/南航=CZ；中国东方航空/东航=MU；厦门航空/厦航=MF；吉祥航空/吉祥=HO。
2. 目的地城市 → destination_city_key：北京=beijing；广州=guangzhou；深圳=shenzhen；成都=chengdu；东京=tokyo。
3. 状态与类型：国内=domestic，国际=international（flight_type_key）；计划中=scheduled，延误/晚点=delayed，取消=cancelled（status_key）。航站楼只能为 T1、T2。
```

字典逐条列全，不要让模型自己翻译。少一个词条，用户换个说法就查不到数据。

### 7.3 默认值映射
```text
# 日期默认映射规则
- 当用户输入"今天"、"今日"或询问某地航班未指定日期时，默认映射为 flight_date=="2026-10-09"。
- 当用户输入"明天"、"明日"时，默认映射为 flight_date=="2026-10-10"。
- 当用户输入"后天"时，默认映射为 flight_date=="2026-10-11"。
- 若用户直接通过具体航班号查询，则只按 flight_no 过滤，不加日期限制！
```

"未指定日期"必须有默认分支。写"今天被拦截返回空"这类规则时，同步写清演示环境需要什么默认值。

### 7.4 ASCII 红线
```text
X-JSON-Path 将作为 HTTP 请求头发送：整个表达式只允许 ASCII 字符，禁止中文、换行和 Unicode 字符。
```

HTTP header 只接受 ASCII。中文一旦进 header，底层报 `'ascii' codec can't encode characters`。这条红线写进转换节点，不要靠人工在测试框里手填。

### 7.5 示例给到能直接抄
```text
# 示例
输入：今天飞北京的东航什么时候飞
json_path：$.flights[?(@.flight_date=="2026-10-09" && @.airline_code=="MU" && @.destination_city_key=="beijing")]
输入：查一下 CA1837 准点吗
json_path：$.flights[?(@.flight_no=="CA9901")]
输入：请查询全部已存航班
json_path：$.flights[*]
```

示例覆盖多条件组合、单字段查询、全量查询三种形态。只给一种，另外两种模型会自创语法。

## 八、上下文 / USER / SYSTEM 三者分工

| 位置 | 只放 | 不要放 |
|---|---|---|
| 上下文（Context） | 参考资料：知识库召回、HIS 接口返回、上游节点输出 | 用户原话 |
| USER | 本轮用户输入 `sys.query` | 参考资料、历史轮次 |
| SYSTEM | 角色、任务、红线、格式、范例 | 需要模型读取的动态数据（用变量引用） |

三种常见错配，都会让模型"看不见输入"或"看到两份输入"：

| 错配 | 后果 |
|---|---|
| 数据放进上下文，SYSTEM 里没有变量引用 | 系统弹黄字"要启用上下文功能，请在提示中填写上下文变量"，模型实际收不到数据 |
| 用户原话只放进上下文，没加 USER 消息 | 模型输入框为空，按规则输出 UNKNOWN |
| 用户原话同时进上下文和 USER | 提示词变长，模型重复理解，输出格式不稳定 |

检查顺序：SYSTEM 里每份数据都有对应变量气泡，且是 `{x}` 插入的带底色块而非手敲文本 → USER 消息存在且插入了 `sys.query` 气泡 → 上下文栏里没有与本节点职责无关的变量，提取类与转换类节点保持为空 → 上游节点输出变量已登记。

## 九、提示词长度与响应延迟

| 事实 | 处理方式 |
|---|---|
| 提示词越长，模型注意力越被稀释，越容易分心执行错分支 | 每个节点只留本职责的红线与范例，公共规范最多 4~6 条 |
| 长提示词抬高首字延迟，播报类、数字人场景对延迟极敏感 | 播报节点只做语言组织，字段筛选与聚合放上游代码节点 |
| 只做分类、分发、简单文本输出的节点不需要强推理 | 选轻量快模型（如 Doubao-lite 级别），省钱且快 |
| 全量人设塞进单个节点后已实测出现答非所问、误吐无关内容 | 拆节点，不靠"再补几条红线"修 |

判断方法：某节点提示词超过一屏且包含两个以上业务动作，就该拆。

## 十、交付前自检

| 检查项 | 通过标准 |
|---|---|
| 节点职责与人设拆分 | 一句话说清唯一输出物，没有把整版人设复制到多个节点 |
| 变量引用 | 全部用 `{x}` 插入，无手敲变量名 |
| USER 消息 | 每个消费用户输入的节点都有 USER 且插入了 `sys.query` |
| 范例 | 提取类、转换类节点各有至少 2 条 few-shot |
| 缺省值 | 每个提取字段都写了"没提到时填什么" |
| 场景兜底 | 打招呼 / 无关 / 无召回 / 正常 / 负面情绪 五类齐全，红线各有触发条件、唯一替代动作、豁免说明 |
| 输出标记 | `[END]` `[SUCCESS]` 被下游条件分支消费，不直接透传前端 |
| 格式 | 播报节点四条格式红线齐全（纯文本、去列表、去角标、禁括号） |
